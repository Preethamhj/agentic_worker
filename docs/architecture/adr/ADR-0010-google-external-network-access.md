# ADR-0010: Google external network access boundary

Status: accepted for network-policy implementation, 2026-11-08. This ADR
amends the network boundary only. It does not authorize implementation of
Calendar, Gmail, Drive, or Meet operations.

## Context

Jarvis is local-first. The AI server uses Python and local Ollama; Google
OAuth/API requests need a narrowly controlled transport in the C# Windows
host. The existing Python socket guard remains active and must continue to
deny every non-loopback destination. The C# host must not turn this exception
into arbitrary external networking.

## Decision

- Google network access is disabled when the optional
  `integrations.google.network_policy` setting is missing or disabled.
- When enabled, only HTTPS on port 443 to exact hosts and endpoint paths in
  this table is approved. No wildcard domains are used.
- OAuth token exchange and refresh, ID-token signing-key retrieval, and
  generated Google API clients use the same `GoogleApiClientFactory`.
- DNS is performed only after the hostname passes the exact allowlist check.
  The connection callback rejects non-public address results and connects to
  the validated address; normal .NET TLS certificate validation remains
  enabled. System proxies are disabled to prevent proxy-side DNS or routing
  from bypassing the destination check.
- Automatic redirects are disabled. Redirects are not followed; the handler
  rejects destinations outside the same endpoint policy.
- API requests are limited to `GET` and `HEAD`; token exchange/refresh and
  revocation use `POST`; the authorization URL and ID-token signing-key
  endpoint use `GET`.
  Future write operations require a separate policy amendment.
- Request timeout defaults to 30 seconds and is configurable from 1 to 120
  seconds. Cancellation is passed to HTTP, DNS, and socket operations.
- Google.Apis.Auth 1.78.0's ID-token validation API has no cancellation-token
  parameter; its certificate fetch is bounded by the configured HTTP timeout.
- Python does not call Google and does not receive OAuth tokens. Tokens remain
  in the C# DPAPI-backed credential store.

## Approved minimum endpoints

| Purpose | Exact HTTPS host and path |
|---|---|
| OAuth authorization URL generated for the system browser | `accounts.google.com/o/oauth2/v2/auth` and `accounts.google.com/o/oauth2/auth` |
| OAuth token exchange/refresh (OIDC endpoint) | `oauth2.googleapis.com/token` |
| OAuth token exchange/refresh (Google .NET library's non-OIDC endpoint) | `accounts.google.com/o/oauth2/token` |
| OAuth token revocation | `oauth2.googleapis.com/revoke` |
| ID-token signing-key retrieval by Google.Apis.Auth 1.78.0 | `www.googleapis.com/oauth2/v3/certs` |
| Calendar API | `www.googleapis.com/calendar/v3/` |
| Gmail API | `gmail.googleapis.com/gmail/v1/` |
| Drive API | `www.googleapis.com/drive/v3/` |
| Meet API | `meet.googleapis.com/v2/` |

These are path-prefix rules with a path-segment boundary, not host suffix
rules. Other Google endpoints, Googleusercontent media downloads, batch
endpoints, Google discovery, and all non-Google hosts remain denied until
separately reviewed and explicitly added.

The endpoint selection is grounded in Google's OAuth desktop-app and web
server documentation, the Google Calendar `events.list`, Gmail
`users.messages.list`, Drive `files.list`, and Meet `spaces.create` REST
references, and the Google.Apis.Auth 1.78.0 OAuth and ID-token URL constants.
The Gmail hostname is `gmail.googleapis.com`, not the initially considered
`www.googleapis.com`. Meet uses `meet.googleapis.com`.

## Enforcement and limitations

`GoogleHttpMessageHandler` validates each HTTP request, destination path,
redirect response, and host header. Its `SocketsHttpHandler` resolves the
allowlisted DNS name, rejects local/private/special-use results, disables
proxying and auto-redirect, and uses the platform TLS validation defaults.
`GoogleOAuthService` supplies the controlled `IHttpClientFactory` to both
the authorization-code flow and Google ID-token certificate validation.
`GoogleApiClientFactory.CreateService` configures generated Google API
services with that same factory.

The system browser launched for OAuth is a separate process, not a .NET
`HttpClient`; the handler cannot constrain browser page loads or redirects.
The authorization URL is generated by the Google library, while token and
certificate requests made by the .NET library use the controlled factory.
The WPF application composes Google account management through
`GoogleAccountServices`. OAuth token exchange, refresh, ID-token certificate
retrieval, revocation, and the Calendar/Gmail readers use the controlled
factory. Future API services must be created with
`GoogleApiClientFactory.CreateService`; direct construction or the Google
library's default factory is not covered. Per-service settings control API
paths and OAuth scopes, and require an application restart to take effect.
See [ADR-0011](ADR-0011-google-calendar-gmail-read-only-ui.md) for the UI
read-only scope and its distinction from tool execution.

The endpoint policy is not a per-operation API method policy. Its paths allow
traffic to each listed API service, and future operation-level read/write
restrictions must be enforced separately by scopes and the authorization
model. No live Google request was used for policy tests.
